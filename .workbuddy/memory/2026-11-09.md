- **一次点击两个包**：右键倒出 bundle 时客户端把「内容被改过的冰柜」写回原槽（`currentCooler && cursorCooler` 的槽位包）+ 把倒出的占位物放光标。旧代码在 `currentCooler && cursorCooler` 分支只 `setCancelled` 就 `return`，第一次右键毫无反应；等玩家把占位物点到别的格子（第二个包，`spilled=true`）才走到 `openCooler` 关栏 —— 正是用户描述的「直到放下物品才撤回并关栏」。左键拿起/放下则是 `cursor` 为空或整只冰柜的包，旧代码对它 `setCancelled + openCooler`，导致关栏、永远放不进主手。
- **新分流**（`handleCreativeClick` 四段）：① OUTSIDE 包全部放行，只有 `spilled` 时取消撤回，**不触发动作**；② 槽位包 `currentCooler && cursorEmpty`（拿起清空）/ `!currentCooler && cursorCooler`（放到空格）完全放行，左键零操作；③ 与冰柜无关的槽位包放行，仅当 `spilled && withinCreativeWindow` 时撤回残留占位物（避免误伤玩家自己的普通玻璃瓶/冰）；④ 点到冰柜槽位且 cursor 不空 → 取消 + `setCursor(null)` + 当场触发动作。同一次点击的两个包用 `claimCreativeAction`（UUID→时间戳，250ms 窗口）去重。

- **顺带修复**：`onInventoryClick` 把 `inCoolerGui` 判断提到 CREATIVE 分支之前。创造模式在**冰柜 GUI 内**点击也会发 `InventoryCreativeEvent`，旧顺序会把它误判成「往 bundle 塞果汁」而走 `putIn` 重复插入；现在 GUI 内只按 `rawSlot < top.getSize()` 判断 incoming 并过滤非果汁。

## 迭代：创造模式打开已初始化冰柜后残留幽灵玻璃瓶

- **现象**：创造模式下初始化前一切正常；已初始化的冰柜右键能打开 GUI，但关掉 GUI 再打开原版物品栏，光标/背包里会出现 `used` 个玻璃瓶（正好是容量条占位物的数量）。
- **根因**（javap `folia-26.3.jar` `handleSetCreativeModeSlot` 字节码 321~409）：`Result.DENY` 分支先 `packet.slotNum() < 0 ? return : ...`。即槽位包 DENY 会回发真实槽位 + `ClientboundSetCursorItemPacket(EMPTY)`，但 **OUTSIDE 光标包 DENY 直接静默 return，什么都不发**。客户端右键 bundle 时本地预测把占位物画到光标上，槽位包的清空包先到、光标包的静默 return 后到，幽灵玻璃瓶就留在客户端 carried item 里；随后 `openBackpack` 切换容器也不会清它。未初始化路径多了 `closeInventory()` 强制重同步，所以一直没暴露。
- **可用的同步手段**：`CraftHumanEntity#setItemOnCursor(ItemStack)` 反编译确认会 `containerMenu.setCarried(...)` 并（CraftPlayer 时）`broadcastCarriedItem()`，等价于主动发 `ClientboundSetCursorItemPacket`；`CraftPlayer#updateInventory()` 只是 `sendAllDataToRemote()`，负责全量回发槽位。两者都不带 `ensureTickThread`，但调用点仍放在玩家实体线程。
- **修法**（全部在 `VisableCooler.java`）：
  1. 静态 `NamespacedKey("cyantestaddon", "vc_placeholder")`（不用 Plugin 构造，注册前的静态模板也能打标），`createFiller` / `createIcePlaceholder` 给占位物写 PDC BYTE 标记。`createFiller` 里 maxStackSize 与 PDC 一次 `setItemMeta` 写完，避免互相覆盖。客户端从 `bundle_contents` 取出的是完整 ItemStack，标记能读回来。
  2. `clearCreativeCursor`：OUTSIDE 包 cancel 后显式 `setItemOnCursor(服务端真实光标)` 广播，覆盖客户端预测；只清带标记的物品，玩家自己的玻璃瓶原样重发。
  3. `purgeLeakedPlaceholders`（`schedulePurge` 用 `runAtEntity` 调度）：重发光标 + 删除玩家各槽里带标记的占位物 + `updateInventory()` 全量回发。调用点在 `openCooler`（创造模式，且先 `closeVanillaOverlay`）与 `onBackpackClose`（关 GUI 后下一 tick）。
  4. `onInventoryClick` 开头兜底：`current`/`cursor` 带标记就 cancel + 清光标 + 调度回收，防止幽灵物被"放下"后变成服务端真实物品。
  5. 宽松识别 `isLoosePlaceholder`（GLASS_BOTTLE 数量 1..36 / ICE×64、无自定义 meta）只在 `creativeSpillAt` 的 15 秒回收窗口内生效；OUTSIDE 光标包例外地无条件宽松识别（否则 PDC 丢失且槽位包后到时会放行甚至把物品掉到地上），但只做撤回、不触发关栏/提示。刷新窗口只由「带标记」或「真实右键动作」触发，防止宽松匹配自激导致窗口永不过期。
