- **一次点击两个包**：右键倒出 bundle 时客户端把「内容被改过的冰柜」写回原槽（`currentCooler && cursorCooler` 的槽位包）+ 把倒出的占位物放光标。旧代码在 `currentCooler && cursorCooler` 分支只 `setCancelled` 就 `return`，第一次右键毫无反应；等玩家把占位物点到别的格子（第二个包，`spilled=true`）才走到 `openCooler` 关栏 —— 正是用户描述的「直到放下物品才撤回并关栏」。左键拿起/放下则是 `cursor` 为空或整只冰柜的包，旧代码对它 `setCancelled + openCooler`，导致关栏、永远放不进主手。
- **新分流**（`handleCreativeClick` 四段）：① OUTSIDE 包全部放行，只有 `spilled` 时取消撤回，**不触发动作**；② 槽位包 `currentCooler && cursorEmpty`（拿起清空）/ `!currentCooler && cursorCooler`（放到空格）完全放行，左键零操作；③ 与冰柜无关的槽位包放行，仅当 `spilled && withinCreativeWindow` 时撤回残留占位物（避免误伤玩家自己的普通玻璃瓶/冰）；④ 点到冰柜槽位且 cursor 不空 → 取消 + `setCursor(null)` + 当场触发动作。同一次点击的两个包用 `claimCreativeAction`（UUID→时间戳，250ms 窗口）去重。
- **动作归属**：`!isInitialized && !isHeld` → `closeCreativeOverlay`（事件线程立即关一次 + `runAtEntity` 下一 tick 补关一次，应对客户端重画浮窗）+ 发 `NOT_HELD` 提示，绝不调 `openBackpack`；在主/副手（含选中的快捷栏）或已初始化 → `openCooler` 走 Slimefun 命名/打开 GUI。`getItemHandler` 手持右键路径仍走 `parent.onRightClick`（`SlimefunBackpack` 的 handler 会 `e.cancel()` + `openBackpack`），因此「快捷栏使用进入命名流程」不受影响。
- **顺带修复**：`onInventoryClick` 把 `inCoolerGui` 判断提到 CREATIVE 分支之前。创造模式在**冰柜 GUI 内**点击也会发 `InventoryCreativeEvent`，旧顺序会把它误判成「往 bundle 塞果汁」而走 `putIn` 重复插入；现在 GUI 内只按 `rawSlot < top.getSize()` 判断 incoming 并过滤非果汁。
