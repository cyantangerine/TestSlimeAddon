## 修复 Slimefun4 (Folia) 打开背包时 UnsupportedOperationException

仓库：`C:\Users\Elvin\Desktop\GitHub\Slimefun4`（Gradle Kotlin DSL，Java 21，Spotless/Palantir）。

- 现象：`BackpackListener` 报 `Exception Occurred During Opening PlayerBackPack`，`CompletionException` → `UnsupportedOperationException` → `MCUtil.lambda$static$0` → `MinecraftServer.execute`。
- 根因：`ThreadUtils` 静态块反射 `io.papermc.paper.util.MCUtil.MAIN_EXECUTOR`；该类在 Folia 上仍存在，所以 catch 兜底不触发，而该 Executor 会调到 Folia 已废弃的 `MinecraftServer#execute()`。`BackpackListener` 用 `.thenAcceptAsync(..., ThreadUtils.getMainThreadExecutor())` 投递回调，异常在 `UniAccept.tryFire/claim` 阶段抛出，回调体完全没执行，导致 `openingPlayers` 残留、玩家交互被全部取消。
- 改动：
  - `BackpackListener.java`：改用 `.thenAccept(...)` + `Slimefun.runSyncAtEntity(..., 0, p)`（实体归属线程）；`openBackpack` 里对 `PlayerProfile.get` 可能落在 DB 线程的回调加 `Bukkit.isPrimaryThread()` 分流；新增 `PlayerQuitEvent`/`PlayerKickEvent` 清理三个 map；两个 `.exceptionally` 都兜底移除 `openingPlayers`。
  - `ThreadUtils.java`：静态块先用 PaperMC 官方推荐的 `Class.forName("io.papermc.paper.threadedregions.RegionizedServer")` 检测 Folia，命中时改用 `Slimefun::runSync`（全局区域调度器），Paper 保留原 NMS 反射；补充 Javadoc 说明涉及实体/方块必须用 `runSyncAtEntity`/`runSyncAtLocation`。
  - `PlayerBackpack.java` / `IAsyncReadCallback.java`：补充 Folia 全局线程不拥有玩家的文档警示（未改行为）。
- 约定（本项目已确立）：Folia 上玩家/实体操作一律 `Slimefun.runSyncAtEntity`，方块/位置操作一律 `runSyncAtLocation`；`getMainDelayedExecutor()`（全局区域调度器）不能用于实体操作。参考 `CoolerListener.java` 与 `AbstractCraftingTable.java` 里已有的同类修复。
- 验证：`./gradlew.bat build --no-daemon` → BUILD SUCCESSFUL（含 spotlessCheck 与 test），产物 shadowJar 正常生成。
